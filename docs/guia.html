O Guild roda no Claude Code. É lá que as guardas existem: a mesma skill aberta em outra ferramenta roda sem nenhuma delas.

Quase tudo é guiado por uma skill dentro do Claude Code. O que você faz à mão é só a preparação da máquina, uma vez:

EtapaQuem fazQuando
1. Preparar a máquinavocê, no terminal (~10 min)uma vez por máquina
2. Configurar o repositórioa skill /guild-inituma vez por repositório
Depoisa skill /guild-upgradea cada versão nova da plataforma

Passos marcados com Azure Boards só valem para o time que controla o trabalho num board do Azure DevOps. Com o board em modo local, pule-os.

O que é o Guild, em 30 segundos

PeçaO que é
SkillsProcessos de engenharia que a IA executa (/guild-init, /codebase-analysis, …)
AgentesUm agente dev por camada da arquitetura, cada um com sua fronteira de escrita
CLI rbbA parte mecânica: board, sincronização, perfil, verificação. As skills o chamam por você
GuardasHooks do Claude Code que bloqueiam de verdade escrita fora da fronteira do agente

O catálogo completo — cada skill, comando e agente, com o que recebe e o que gera — está em https://rabberto.github.io/rbb-guild/. Ele mostra a versão mais nova da plataforma; a instalada na sua máquina responde em rbb version. Sentiu falta de algo do catálogo? Sua versão pode ser mais antiga: rode /guild-upgrade.

Etapa 1 — Preparar a máquina

Nada disto pode ser feito por skill: ou é o que faz as skills existirem (o CLI), ou é segredo (tokens), que as skills nunca pedem nem gravam.

1.1 Pré-requisitos

FerramentaOnde instalar
Node.js (LTS), que traz o npmhttps://nodejs.org/en/download
Git (no Windows, já traz o Git Bash)https://git-scm.com/downloads
Claude Code: onde rodar, na 1.6https://code.claude.com/docs/en/setup

Windows: as três pelo winget, no PowerShell (o Git Bash só existe depois que o Git for instalado):

winget install --id OpenJS.NodeJS.LTS -e
winget install --id Git.Git -e
winget install --id Anthropic.ClaudeCode -e

E o acesso ao feed do CLI — é o único acesso necessário: skills, agentes e templates vêm dentro do pacote. Quem distribui o Guild para o seu time libera o acesso e passa a URL do feed.

Depois de instalar, feche e abra o terminal: só um terminal novo enxerga o node, o npm, o git e o claude recém-instalados.

Windows: daqui em diante, use o Git Bash. No PowerShell, o comando bash é o do WSL — outro sistema, sem o seu Node. Comandos e gates do Guild rodados por ali falham com mensagens enganosas.

1.2 Autenticar o npm no feed do Guild

O CLI é distribuído por um feed npm do Azure Artifacts. Grave a URL do feed, que vem de quem liberou o seu acesso, trocando <url-do-feed>:

npm config set @rbbsolucoes:registry <url-do-feed>

O npm config set grava no arquivo de configuração que o npm de fato lê (npm config get userconfig mostra qual), seja qual for o seu terminal.

Agora a credencial. Windows:

npm install -g vsts-npm-auth
vsts-npm-auth -config "$(npm config get userconfig)"

Linux / macOS / WSL: gere um PAT em User settings → Personal Access Tokens com escopo Packaging: Read e adicione-o ao arquivo que npm config get userconfig mostra, no formato de Artifacts → Connect to feed → npm → Other.

Teste:

npm view @rbbsolucoes/rbb-engineering-cli version

Respondeu uma versão? Autenticação OK.

1.3 Instalar o CLI

npm install -g @rbbsolucoes/rbb-engineering-cli
rbb version
rbb configure

O rbb configure, rodado em qualquer pasta, é o passo da máquina: mostra o feed que o CLI encontrou no seu npm e instala as skills de entrada (/guild-init, /guild-help e /guild-upgrade) em ~/.claude/skills. Daqui em diante, todo repositório aberto no Claude Code já tem as três. Com uma sessão do Claude Code já aberta, rode /reload-skills (ou reabra a sessão).

1.4 PAT do board Azure Boards

O Guild lê o PAT de uma variável de ambiente — ele nunca é gravado em arquivo. Gere um PAT com escopo Work Items: Read & Write e defina a variável. O nome é escolha do time: o /guild-init pergunta qual é e grava só o nome em .rbb/boards.json. Na Rbb, AZURE_TEAM_ADM_EXT_PAT:

# Windows (permanente — abra um terminal novo depois)
setx AZURE_TEAM_ADM_EXT_PAT "<seu-pat>"

# bash (Linux/macOS) — coloque no ~/.bashrc ou ~/.zshrc
export AZURE_TEAM_ADM_EXT_PAT=<seu-pat>

Se você já usa o az CLI, AZURE_DEVOPS_EXT_PAT também é aceita.

1.5 Ajuste de git — se o time integra numa develop

Cada time tem o seu fluxo de branch. Este ajuste vale para quem cria as branches de trabalho a partir de origin/develop:

git config --global branch.autoSetupMerge simple

Sem isso, criar uma branch a partir de origin/develop grava o upstream como origin/develop, e o git push passa a sugerir empurrar direto para a develop. Com simple, use git push -u origin HEAD na primeira vez.

1.6 Onde rodar o Claude Code

O Guild roda onde o Claude Code roda. Há três caminhos oficiais, todos do publicador Anthropic:

OndeComo instalar
VS Codeextensão Claude Code, pelo marketplace do VS Code
JetBrains (IntelliJ, Rider, WebStorm…)plugin Claude Code [Beta], pelo JetBrains Marketplace. Ele roda o CLI no terminal integrado da IDE
Terminal, com qualquer editoro CLI, pelo winget do 1.1 ou pelo link da tabela de pré-requisitos

Conferido com o Guild no Claude Code 2.1.322: o /guild-init e a guarda barrando a escrita fora da camada, no CLI no terminal e na extensão do VS Code. O plugin do JetBrains é caminho oficial, mas ainda não foi conferido com o Guild.

A sessão roda na pasta em que é aberta. No VS Code, abra a pasta do repositório (File → Open Folder) antes de começar a conversa. Numa janela sem pasta, a sessão nasce fora do projeto, e a guarda não vale ali.

CLI, guia rápido:

  1. Instale e, num terminal novo, confira com claude --version.
  2. Abra o terminal na raiz do repositório e rode claude.
  3. Rode /guild-init. Num repositório que já adotou o Guild, /guild-upgrade.
  4. No dia a dia, siga a tabela Dia a dia, mais abaixo neste guia.

O terminal não achou o claude? A pasta da instalação não está no PATH. No instalador nativo do Windows, ela é a %USERPROFILE%\.local\bin: acrescente-a ao PATH do usuário e abra outro terminal.

A extensão do VS Code se atualiza com o VS Code. O CLI só se atualiza sozinho com a atualização automática ligada. Para atualizar na hora, rode claude update.

Visual Studio: não há extensão oficial da Anthropic. O caminho recomendado é o CLI no terminal integrado (Exibir → Terminal), com o guia rápido acima. Ele ainda não foi conferido com o Guild dentro do Visual Studio.

Existe uma extensão da comunidade, Claude Code Extension for Visual Studio (dliedke.ClaudeCodeExtension, VS 2022 e 2026, só Windows). Fica só como sugestão: não é oficial, é mantida por uma pessoa, não tem suporte da Anthropic e não foi conferida com o Guild. O ideal é usar o VS Code, o JetBrains ou o CLI.

Segurança: instale só pelo marketplace oficial de cada editor, conferindo que o publicador é a Anthropic. Nunca instale um .vsix baixado de outro lugar: já houve build adulterada da extensão num marketplace de terceiros.

Etapa 2 — Configurar o repositório

Nada aqui é à mão. Abra o Claude Code na raiz do repositório e execute:

/guild-init

A skill lê o que já existe, mostra um plano antes de agir e conduz o resto. Você responde às perguntas; ela explica cada escolha.

#O que acontece
1Confere a configuração e traz skills e agentes para o repositório
2Conecta o board — modo (Azure Boards ou local); em Azure Boards, também organização, projeto, nome da variável do PAT e mapeamento de estados, e testa a conexão
3Gera o perfil do projeto (.rbb/project.yaml) com codebase-analysis, se não existir
4Atualiza no perfil o que é verificável (dependências)
5Deriva um agente por camada e instala os hooks de guarda
6Verifica a máquina e o projeto, inclusive se a guarda está viva, e não só registrada — vermelho deixa a adoção como pendente

Mapeamento de estados do board [Azure Boards]: responda com os estados reais do processo do seu board, não com o preset "mais parecido". Estado que não existe no board faz a guarda recusar transições legítimas depois.

Depois dos hooks, a skill pergunta se você quer liberar a edição de arquivos, a leitura do git e do shell (git status, git log, git rev-parse, ls, grep…) e o build e teste da stack, para o Claude parar de pedir aprovação no rotineiro. Só o que você escolher é gravado, no .claude/settings.local.json: o arquivo é seu, fora do git, e não do time. Apagar arquivo segue perguntando, a menos que você peça para liberar também. As leituras da plataforma (o diagnóstico, a versão, o estado da guarda) já vêm liberadas para o time, no .claude/settings.json.

Em seguida, ela oferece uma notificação do sistema para quando o Claude precisa de você. Ela também fica no .claude/settings.local.json, só com o seu sim. O que cada lugar avisa, conferido no Claude Code 2.1.322:

Onde você rodaAprovação de comando pendenteParado esperando vocêFim de cada turno
CLI no terminalavisaavisa, depois de um minutonão avisa: a espera já cobre
Extensão do VS Codeavisanão disponívelavisa, no lugar da espera
Plugin do JetBrainsnão provadonão provadonão provado

A aprovação só avisa se ficar uns segundos sem resposta: quem está olhando a tela não recebe aviso. Se você já tem um aviso seu configurado, a skill diz onde e pergunta qual manter, para você não receber dois. Com o seu sim, a skill dispara um aviso de teste na hora. No Linux, o aviso precisa do notify-send: se faltar, ela diz o pacote que resolve.

Parou no meio? Rode /guild-init de novo — ela confere o estado antes de cada passo e não destrói configuração existente.

Trabalho em aberto já existente Azure Boards

Só se o time está passando do board local para o Azure Boards e o repositório já tem backlog, planos ou documentos de trabalho em docs/. Rode uma vez:

/board-adoption

Ela leva esse trabalho para o board, para não existirem dois controles em paralelo. Com o board em modo local, não há o que fazer aqui.

Precisa trabalhar sem a guarda?

É o único comando do dia a dia que nenhuma skill faz por você:

rbb guard off     # desliga
rbb guard on      # religa

O rbb guard off desliga só a guarda de escrita, só para quem roda e só naquela máquina. Os hooks continuam registrados no .claude/settings.json do time, e a guarda segue valendo para todos os outros. O desligamento fica registrado no ledger, e o rbb guard status diz desde quando está desligada.

Versionar

Commite o que a adoção gerou (.claude/, .gitignore, .rbb/project.yaml, .rbb/boards.json e, se existir, .rbb/config.json) numa branch e abra PR, pelo fluxo de branch do seu time. O .gitignore já vem com as regras certas: o resto de .rbb/ é estado local e fica fora do git.

Depois — mantendo em dia

Saiu versão nova da plataforma, ou algo do Guild falhou por configuração? Abra o Claude Code no repositório e rode:

/guild-upgrade

Ela faz o upgrade inteiro, na ordem certa: atualiza o CLI, as skills e os agentes do repositório e as skills de entrada da máquina, o perfil, o time e os hooks, e termina verificando tudo. O que faltar configurar ela pergunta no chat em vez de deixar o comando falhar.

Ela não pede tokens: se faltar autenticação no feed, ela mostra o que fazer e você refaz o passo 1.2.

Como saber que saiu versão nova: a verificação que o /guild-init e o /guild-upgrade rodam no fim avisa quando o feed tem um CLI mais novo que o instalado, com as duas versões. É só um alerta: atualizar não é obrigatório, e o resto da verificação não muda.

Perfil sem mesa redonda. O time de agentes só se regenera de um perfil que a mesa redonda aprovou: três revisores independentes conferem o perfil contra o código antes de o time ser gerado. Todo perfil anterior à mesa não a tem, então o /guild-upgrade atualiza tudo, reinstala a guarda e termina pendente, pedindo que você rode /guild-init: ele refaz a análise com a mesa e gera o time de novo. É uma vez por projeto, e o time atual segue valendo até lá.

O checkpoint antes de implementar

Quem analisa carrega o contexto todo, e conduzir a implementação nessa mesma sessão custa tanto quanto os subagentes. Por isso o Guild recusa o primeiro despacho de implementação até você decidir onde ela roda. A recusa não é erro: é a pergunta que o /orchestrator vai te fazer, junto com o que a regra sugere para conduzir.

  • Seguir nesta sessão: diga ao orchestrator que segue. A decisão é gravada e a implementação começa.
  • Parar e conduzir em sessão nova: diga que quer parar. O orchestrator escreve um resumo selado do que só a conversa sabe (decisões que não foram para documento nem para card, o que não refazer, o que está em aberto) e pausa o fluxo. A sessão nova lê o resumo e segue de onde parou, sem repetir o que você já aprovou.

Quem grava tudo isso é o orchestrator: você só diz o que quer a ele.

Depois de parar, a sessão que parou não conduz mais: o Guild recusa qualquer despacho dela, mesmo que outra sessão já tenha assumido o fluxo. Se você mudar de ideia, diga ao orchestrator, com o motivo: o motivo vai ao registro do fluxo.
